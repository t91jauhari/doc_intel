# Extraction prompt review and proposed descriptions

Status: proposal only. No application code, schema, settings, prompts or provider jobs were changed.

## Evidence and limits

Reviewed the attached comparison workbook (exported 2026-10-07 19:38:57 UTC), the seven shipped engine profiles, provider configuration, comparison policy and eKTP validation. The workbook contains four customer scenarios and 652 field comparisons: 209 exact matches, 6 fuzzy matches, 42 mismatches, 16 missing values, 77 reviews, 19 unmapped fields, 10 missing-document fields and 273 not-applicable rows. The pooled accepted rate is 215/273 = 78.75%; comparison coverage is 273/379 = 72.03%. Neither number is measured OCR accuracy. All four case summaries have incomplete coverage.

Current below means the descriptions and prompts in the supplied source tree, not a verified snapshot of the actual configuration used for every exported job. Settings can override these instructions. The workbook does not include original source page images, raw extraction, Parse output or resolved job configuration; therefore an effective-value difference cannot establish whether OCR, extraction, normalization, reference transcription or mapping caused it. Dataset anchors are hypotheses for source checking, not permission to overwrite actual document evidence.

## Proposed sequence

1. Confirm actual job schema/prompts/version and inspect source crops for the flagged rows; compare raw Parse, raw extraction and final effective values.
2. Separate reference-format/mapping/normalization issues from genuine transcription and field-assignment errors. Preserve disputed reference values until checked against original documents.
3. Trial concise document-specific Parse prompts, retaining layout/checkbox evidence, and targeted field descriptions below. Keep the strong existing extraction rules; add the document-specific verification clauses shown below.
4. First test extraction-only changes against fixed existing Parse results. Separately test Parse changes with extraction fixed. A changed Parse prompt requires a new Parse run; do not attribute two changed stages to one prompt improvement.
5. Evaluate on the four reviewed scenarios, then on original documents for other customers and layouts not used to design these prompts. Report per-document and critical-field exact accuracy, coverage, false-present detections and review rate separately.
6. Accept only changes that reduce verified errors without inventing values, hiding uncertainty or regressing existing correct fields. A 99% target needs a representative labelled test set; this workbook cannot demonstrate or guarantee it.

## Findings that prompts must not conceal

- eKTP policy uses case-insensitive exact enum matching. Its religion list contains Buddha, while the comparison references include BUDHA. A correctly extracted literal BUDHA could consequently normalize to null; raw values must be checked before calling this extraction failure. Other null enum values need the same trace.
- Valas 2 currency reference CNY 3248 is incompatible with a currency-only field; CNY is the appropriate output if that is the entered currency. Do not add an amount to satisfy the reference.
- Objects/arrays such as beneficiary, remitter and invoice line items often compare against flat text and are REVIEW. Preserve the schema; explicit comparable reference representations are a separate task. A REVIEW row can still hide wrong text or a missing amount inside an object.
- Malformed placeholders such as [BLANK} / [BLANK]) and annotated Available values are not clean comparison references. Blank versus false and absent-object versus all-null-object conventions also need agreed comparison semantics.
- Numeric spreadsheet cells can lose intended separator meaning: Sri total reference is stored as 59.765, while output is 59765; Langit LLD reference is stored as 921.888. Inspect the original written amounts before deciding either output is wrong.
- Account-number spacing and bilingual labels can differ despite faithfully preserved raw source text. Handle approved formatting/label normalization downstream rather than rewriting extraction evidence.
- Invoice Ship To and other UNMAPPED columns cannot be produced by description changes within the current schema. Missing documents and visual identity/authenticity review are also not prompt failures.
- A leading apostrophe on a blood-type dash may be Excel export escaping, not extracted text. Compare the stored effective value before changing prompts.
- Dataset bank spelling Public Bank Berhard differs from output Public Bank Berhad; reference payer-ID length and conflicting SWIFT references also require source verification. Never force the output to a possibly incorrect reference.

## Official guidance and application to this engine

The current engine already sets OCR languages id/en, forms enrichment, spatial text, granular word/line/cell boxes, citations and confidence. These are existing capabilities, not proposed additions. Source: engine/run.py parse_config and extract_config; backend/app/provider.py invokes them and applies configured prompts/schema.

- [Custom instructions](https://developers.llamaindex.ai/llamaparse/parse/features/custom-instructions/): document-specific, concise Parse prompts steer preserved layout/content. Proposed Parse replacements below keep this job focused without demanding extraction JSON.
- [Configuring Extract](https://developers.llamaindex.ai/llamaparse/extract/guides/configuring-extract/): review field descriptions and system-level rules together; preserve schema compatibility and test targeted iterations.
- [Forms and checkboxes](https://developers.llamaindex.ai/llamaparse/parse/features/forms-and-checkboxes/): inspect enriched form fields, blank states, local marks and field boxes when available. Enrichment is beta; failed form pages require review, not invented values.
- [OCR and languages](https://developers.llamaindex.ai/llamaparse/parse/features/ocr-and-languages/): language configuration helps image OCR, but source quality still limits recovery. Camera correction applies to supported image inputs, not PDFs; it is not a general PDF fix.
- [Extract response format](https://developers.llamaindex.ai/llamaparse/extract/guides/response-format/): use resolved configuration, source citations and confidence to trace questionable fields. Bounding boxes belong in provider metadata and evidence processing, not invented by wording a prompt. Confidence is a review signal, not a measured accuracy guarantee.
